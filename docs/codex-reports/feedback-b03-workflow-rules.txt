response fields, because a null uninvoiced amount cannot tell a caller without
money access whether that warning is needed. No amount is leaked in that flag.

The client summary reads a scoped latest trip, including route/date/status;
no trip displays No trips yet.

R2-T2 — DONE. The pending-trip approval banner offers Edit financials to an

then scrolls/focuses the section after loading. No new write endpoint.

R2-C1 — DONE. leadSourceOther is on separate create/update DTOs and the shared

3. Implementation decisions

- EARNED wiring: the exported commission-owned function
  earnOnTripCompletion(tx, tripId, actorId), with no CommissionsModule import
  into TripsModule. Both status completion and the last live leg landing call
  it. Conditional PENDING updates produce one audit per changed commission.
  Its amount is computed with the existing commission/pricing owners, never
  stored as another commission total. Transactional audit writes use tx.auditLog
  directly: the normal AuditService deliberately swallows failures outside a
  transaction, which would not satisfy this brief's atomic consequence.
- Departure-time field: TripLeg.departureTime on the first live leg, ordered by
  sequence ascending. operatorConfirmedAt is the stored operator tick.
- Latest trip: most recently created live trip, ordered createdAt DESC then id
  DESC. ClientsService checks client scope first and calls TripsService, which
  also applies the caller's trip scope. The projection contains no financial
  fields; optional flight facts remain honest blanks. This reuses the existing
  summary markup rather than restoring invented data from an old design.
- Client ownership: QuotesService calls ClientsService rather than writing the
  Client model. The existing Clients → Trips → Quotes read dependencies require
  forwardRef on the new cycle's services/modules; a Nest resolution regression
  test pins it. The commission completion wiring introduces no such DI cycle.
- Open items: a small reader module sits above Trips, Operator Payments and
  Receivables, avoiding an import of those dependants into TripsModule.
  operatorBalance requires OPERATOR_PAYMENTS · VIEW, and uninvoiced requires
  RECEIVABLES · VIEW, matching the existing trip money readers. Both flags
  remain available. An assigned operator with no bill warns but supplies null
  balance; an unpriced trip supplies null uninvoiced rather than invented zero.
- OTHER free text is trimmed and bounded to 500 characters; only the reference
  had a specified length in the brief (120). oaRequired explicitly accepts null
  on both DTOs because this field is deliberately three-valued.
- Shared UI changes are additive: ConfirmDialog pending and PaymentForm optional
  visibility/length props leave existing callers' defaults intact. Paid-only
  inputs are hidden and omitted when the caller lacks COMMISSIONS · PAY.
- Durable AGENTS.md additions: atomic EARNED on every completion path; a method
  for PAID and the payee's payout reference; warning-only open money without
  figure leaks; atomic audited automatic client stages; OTHER-source clearing;
  and preservation of the OA null/false distinction.
