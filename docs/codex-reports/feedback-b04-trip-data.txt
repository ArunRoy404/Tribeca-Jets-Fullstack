2. Per item

R3-04 — DONE. Interior quote upload validates like exterior on both DTOs, returns through list/detail selects, appears beside exterior in the shared quote preview/gallery and PDF, and is included in portal quote responses/PDF. Each photo falls back to the selected aircraft. Quote duplication preserves both photos. R3-05 — DONE. Optional integer weightLb 1–1000 is written/read with each trip passenger, edited on the full form and B2 detail-card editor, and shown as e.g. 180 lb only when present. Blank create is absent; blank/null edit clears.
R3-06 — DONE. Optional luggageCount 0–100 and luggageWeightLb 1–10000 on Trip and TripRequest, DTOs/selects/writes/forms included. Luggage sits directly below trip Passengers and beside request passenger count. Staff detail shows only supplied parts (zero bags is retained). D15 excludes these and passenger weights from client preview/PDF/portal selects and merge fields; no client email fields were added.
R2-T1 — DONE. Shared desktop/mobile row action and detail action use Trips · Create, and hide for CONVERTED, LOST or archived requests. Only fromRequest=<uuid> goes in the URL. The existing new-trip page fetches the request through useTripRequest and submits the existing POST /trips with tripRequestId. Visible converted-trip links are on row, mobile card and detail. The owning TripsService reads the latest visible live booking per request, with no new request column or endpoint. Request selection is now rechecked through TripRequestsService in its read reach as well as for client identity; mismatched clients are pinned by a create-service test.
R2-T4 — DONE. GET /clients/:id/passengers checks client scope first (404 outside it), then reads live manifests on live trips in TripsService reach. Trimmed case-insensitive name + DOB de-duplication happens before search/pagination. The most recent trip supplies even a blank weight. The endpoint returns an explicit allowlist including lastTripReference, never passportNumber. Both trip passenger editors use a thin RecordPicker wrapper and retain editable name/DOB/weight. No new table.

Mismatches/assumptions: the brief's opening says five columns but its detailed migration correctly names six; six were added. The request's actual closed status is LOST, not a CLOSED enum, so LOST is excluded from conversion. The Clients Postman source is recapture_clients_examples.py rather than build_clients_folder.py; that is the file updated. No other requested item was skipped.

3. Decisions

Photo link: Trip.quoteId -> Quote, selected through trip.quote in the itinerary service and the raw trip detail used by the build dialog. Itinerary responses expose quotePhotos for edit preview/library suggestions. Trip gets no photo columns and booking stores no photo copies.
Convert placement: row action menu on desktop, the identical menu on mobile cards, and the request detail toolbar. Converted to TJ-123 is a real link on row, mobile card and detail, with a corresponding menu navigation action.
Saved-passenger recency: departure day descending, missing days last, then trip createdAt descending, with trip id/sequence/passenger id ties fixed. No passport reuse: a passport is sensitive and offering it again remains an owner decision; this batch deliberately never returns or copies one.
Durable rule added in AGENTS.md part one: "Passenger weights and luggage are operator data: never on a client document, the portal or a client merge field." The same paragraph records the passport-free saved-passenger rule.
