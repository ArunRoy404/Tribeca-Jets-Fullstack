3. IMPLEMENTATION DECISIONS
- Quote create defaults live in quotes.defaults.ts. Shared FET defaults live in common/money/fet-defaults.ts; updates do not apply create defaults.
- Dashboard field: receivables.uninvoiced, behind exactly the same Receivables VIEW gate as receivables.outstanding. Reports: outstanding.uninvoiced, with its existing financial-report access.
- Receivables owns invoice sums and orchestrates the owner-provided trip totals; uninvoicedCents in trips.figures.ts does the single cents calculation. Draft and sent invoices count; archived and cancelled invoices do not, matching the existing ceiling.
- Empty-leg labels: AVAILABLE and WITH LIVE MATCHES. They overlap: an AVAILABLE leg with a current match appears in both. Stats and Dashboard use the same scoped candidates as cards; historical LOST, CONVERTED and archived enquiries remain candidates by the existing matching rule. Stored MATCHED alone adds nothing.
- Add Client had the same bug as Add Lead: a blank create follow-up sent null. Both now use the lib/form editing convention: omitted on create, null on edit. ClientsService already supplies stage and follow-up defaults; Leads creates through useCreateClient / POST clients.
- The durable AGENTS rule now distinguishes useDeskDefaults for staff forms, useSettings for restricted Settings screens, and useBranding for public branding.
- The quote builder now uses builder_common and explicit final archive requests rather than asynchronous teardown in a test script. No builder or Newman was run.
