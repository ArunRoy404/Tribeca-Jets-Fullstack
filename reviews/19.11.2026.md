###### **Finance / Invoices**



1. Client credit on account. If a client has credit, show it on the client profile. When we raise an invoice for a new trip, give an option to apply that credit so the amount is reduced.
2. Make a proper Invoices section under Finance. All invoices should be in one place, including the ones raised from trips.
3. From the Invoices section we should be able to send any invoice to the client by email.
4. Creating an invoice without a trip should be possible. Selecting a trip will be optional.
5. Show payment due dates on the calendar. Client payments and operator payments should be in different colors, with a short note like “Client payment due” or “Pay operator”.
6. Trip expenses. Add a dropdown with Catering, Transportation and Other (Other will be free text), plus an amount field. This is internal only and the client should not see it. It needs to show in Reports for accounting.
7. Receipt vault under Finance. Users can upload a picture of a receipt. Before saving, they should mark it as Legitimate expense, Potential expense or Non-expense.
8. Only admins can see and edit the wire information in Settings. Brokers should not have access.



###### **FET Accounting (new tab, high priority)**

This tab is for admins only. Brokers can still add client payments on their trips, but they must not be able to open, view, export or email anything in FET. Block it on the backend too, not only in the UI.



1. Auto FET records. When a trip has FET enabled, create an FET entry automatically from the trip data, so nothing is entered twice. Each entry holds: trip number, client, broker, flight dates, airports, booking date, payment date, trip price, taxable amount, FET (7.5%), due date and status.
2. 14-day reminder. Count 14 days from the date the client payment is received, not from the flight date. Example: payment on Nov 1 means the reminder is on Nov 15.
3. Installments. Each client payment gets its own FET entry and its own 14-day reminder. Avoid duplicates and handle partial payments properly.
4. FET-exempt trips should not create an entry. If FET is already included in the price, extract it from the price instead of adding it again.
5. Keep three separate statuses: FET collected, reported to accountant, and paid to IRS.
6. Dashboard with these statuses: Upcoming, Due Soon (within 3 days), Ready/Overdue, and Sent to Accountant. Show totals for collected, pending, ready, sent, outstanding, by month and by quarter. Add filters for date, client, broker and status.
7. Notifications. Alert admins 3 days before the due date, on it, and after it while the entry is still unsent. Show them in the CRM, with email optional. Stop the reminders once an entry is marked sent.
8. “Generate FET Report” button. Admins can pick one entry, several entries, a month, a quarter, a custom date range, or all outstanding entries. Export to PDF, Excel and CSV. The report needs the Tribeca Jets name, the date, client names, booking numbers, flight and payment dates, amounts, FET and a grand total.
9. “Send to Accountant” button. The flow is: select entries, generate the PDF, prepare the email (to the accountant’s email from Settings, with the period, total and PDF attached), admin previews and approves, then send. Mark entries as Sent only after the email goes through successfully. Save the send date and time, the user, the total and the recipient. If sending fails, keep the entries outstanding.
10. Report history. Save every sent report with its report number, date, period, total, number of entries, user, accountant email, delivery status and a PDF download.
11. Admin corrections. Admins can mark an entry sent manually, fix payment dates, adjust amounts, add notes, record full or partial refunds, reopen entries, resend reports and mark entries exempt. Log every change. If an entry was already sent, don’t overwrite it. Create an adjustment record instead.
12. Accountant settings. Save the accountant’s name and email, CC addresses, a default subject and body, and a default reporting schedule.
13. Never auto-send to the accountant for now. An admin must always click Send. Please build it so we can add a daily auto-generated report later.

2. When a broker books a trip, it should go to an admin for approval. The admin can Approve, Edit the markup/financials, or Decline.
3. Trip transfer. A user can transfer a trip to another user. If a broker does it, the broker adds a short note and an admin has to approve it. If an admin does it, no approval is needed.
4. Saved passengers. When we select a client for a new trip, show their past passengers (with DOB and other details) so we can add them with one click.
5. Whenever any trip is booked, all admins and super admins should get an in-app notification and an email.
